Core Web Vitals: drei Werte, die über Ihre Ladezeit entscheiden

„Die Seite ist zu langsam“ ist keine brauchbare Diagnose. Google hat das Problem deshalb in drei Werte zerlegt, die jeweils etwas anderes messen. Wer sie kennt, versteht sofort, woran es hakt — und erkennt, ob ein Angebot am richtigen Ende ansetzt.

LCP — wann sieht der Besucher etwas Großes?

Largest Contentful Paint misst, wann das größte sichtbare Element im ersten Bildschirmausschnitt fertig geladen ist. Meist ist das ein Titelbild oder eine große Überschrift. Der Wert beantwortet die Frage: Wie lange starrt jemand auf eine leere Fläche?

Grenzwert: gut bis 2,5 Sekunden, verbesserungsbedürftig bis 4 Sekunden.

Die häufigsten Ursachen für schlechte Werte:

  • Ein unkomprimiertes Titelbild, oft mehrere Megabyte groß, direkt aus der Kamera hochgeladen
  • Schriften, die von einem fremden Server geladen werden und den Textaufbau blockieren
  • Ein langsamer Server, der schon vor dem ersten Byte Zeit verliert
  • Ein Rutsch aus Skripten im Kopf der Seite, der alles Weitere aufhält

CLS — springt der Inhalt beim Laden?

Cumulative Layout Shift misst, wie stark sich der Inhalt während des Ladens noch verschiebt. Jeder kennt das: Man will auf einen Link tippen, im selben Moment lädt darüber eine Anzeige, alles rutscht nach unten, und man landet woanders.

Grenzwert: gut bis 0,1, verbesserungsbedürftig bis 0,25.

Die Ursache ist fast immer dieselbe: Ein Element wird eingefügt, ohne dass vorher Platz dafür reserviert war. Bilder ohne Angabe von Breite und Höhe sind der Klassiker. Der Browser weiß erst beim Eintreffen des Bildes, wie hoch es ist — und schiebt dann alles darunter weg.

Die Lösung ist billig: width und height an jedes Bild schreiben oder ein aspect-ratio setzen. Dasselbe gilt für nachgeladene Banner, Einbettungen und Hinweisleisten.

INP — reagiert die Seite, wenn man sie anfasst?

Interaction to Next Paint hat 2024 den älteren Wert FID abgelöst und misst, wie lange es dauert, bis die Seite auf eine Eingabe sichtbar reagiert — Tippen, Klicken, ein Menü öffnen. Gemessen wird über den gesamten Besuch, nicht nur beim ersten Klick.

Grenzwert: gut bis 200 Millisekunden, verbesserungsbedürftig bis 500 Millisekunden.

Schlechte Werte entstehen, wenn zu viel JavaScript gleichzeitig läuft. Der Browser arbeitet an einem einzigen Strang: Solange dort ein Skript rechnet, kann er auf nichts anderes reagieren. Typische Verursacher sind Seitenbaukästen mit einem Dutzend Erweiterungen, mehrere Analysewerkzeuge parallel und Karussells, die bei jedem Bildwechsel das Layout neu berechnen.

Labordaten und Felddaten — der wichtigste Unterschied

Hier liegt der häufigste Irrtum. Werkzeuge wie Lighthouse messen im Labor: ein simuliertes Gerät, eine simulierte Verbindung, ein Durchlauf. Das ist gut zum Aufspüren von Ursachen, sagt aber nichts darüber, was Ihre echten Besucher erleben.

Für die Bewertung durch Google zählen die Felddaten — echte Messwerte echter Besucher aus den vergangenen 28 Tagen, gesammelt im Chrome User Experience Report. Deshalb ändert sich Ihr Wert nach einer Umstellung nicht sofort, sondern erst, wenn genug neue Besuche eingeflossen sind.

Wenn jemand nach einer Optimierung am selben Tag „grüne Werte“ meldet, zeigt er Labordaten. Das ist nicht falsch, aber es ist nicht das, was zählt.

Wie Sie selbst nachmessen

  • PageSpeed Insights von Google zeigt beides nebeneinander: oben die Felddaten Ihrer echten Besucher, darunter den Labortest. Kostenlos, ohne Anmeldung.
  • Search Console hat einen eigenen Bereich für Core Web Vitals, gruppiert nach Seitentypen. Zeigt, welche Vorlage das Problem verursacht — nicht nur welche Einzelseite.
  • Entwicklerwerkzeuge im Browser, Reiter Lighthouse. Praktisch für schnelle Vorher-Nachher-Vergleiche während der Arbeit.

Messen Sie im Mobilmodus. Der Unterschied zum Desktop ist meist erheblich, und die Mehrzahl Ihrer Besucher kommt vom Telefon.

Was Ladezeit wirklich bringt

Ehrlich bleiben: Core Web Vitals sind ein Rankingfaktor, aber ein schwacher. Eine schnelle Seite mit schlechten Inhalten überholt keine langsame Seite mit guten Inhalten.

Der Nutzen liegt woanders. Menschen brechen ab, wenn nichts passiert. Eine Seite, die in einer Sekunde steht, verliert weniger Besucher als eine, die vier Sekunden braucht — unabhängig von jedem Ranking. Und für Antwortsysteme gilt: Was zu langsam lädt, wird beim Sammeln schlicht übersprungen.

Deshalb steht Technik bei uns an erster Stelle. Nicht weil sie am meisten bringt, sondern weil ohne sie alles andere ins Leere läuft.
